# HIG Audit — Budgeting PWA — 2026-04-28

## Summary

**Top 3 wins**
1. **Liquid Glass foundation is real, not faux.** The `.glass` utility in [src/index.css](src/index.css#L120-L160) implements all four Apple ingredients — translucent gradient, `backdrop-filter: blur(24px) saturate(180%) brightness(1.05)`, inner highlight, drop shadow — with proper light/dark variants and a `@supports not` fallback. The mobile floating tab bar [src/components/Layout.tsx](src/components/Layout.tsx#L102-L122) and Dashboard lens chips [src/pages/Dashboard.tsx](src/pages/Dashboard.tsx#L41-L58) use it correctly.
2. **Press-feedback is iOS-grade.** `.btn:active { transform: scale(0.94) }` with the spring easing curve `cubic-bezier(0.22, 1.4, 0.36, 1)` ([src/index.css](src/index.css#L83-L105)) is a faithful reproduction of the iOS 17/26 button squish, applied even to non-`.btn` buttons via the generic `button:not(.btn):not([data-no-press])` rule. `-webkit-tap-highlight-color: transparent` is removed correctly.
3. **Mobile dialog adapts properly.** [src/components/ui/Modal.tsx](src/components/ui/Modal.tsx#L20-L100) is a true bottom sheet on `< md`: drag handle, sticky header with safe-area, swipe-to-dismiss via `framer-motion` drag controls (offset > 120px or velocity > 600), `bg-bg-card/95 backdrop-blur-md` header band, `pb-[max(env(safe-area-inset-bottom),12px)]` footer, and `onOpenAutoFocus` prevented to suppress the iOS keyboard pop on open. This is rare to get right on the web.

**Top 5 gaps**
1. **No `prefers-reduced-motion` support anywhere.** Zero matches across the codebase. `framer-motion`'s `<motion.*>` and `animate-*` Tailwind keyframes (`fade-in`, `slide-up`, `sheet-up`) ignore the user's motion preference. WCAG 2.3.3 / HIG accessibility violation.
2. **No haptics.** Zero `navigator.vibrate(...)` calls. iOS 17.4+ supports `vibrate()` in standalone PWAs; HIG actively recommends light haptics on save / destructive / success. Big perceived-quality gap for a PWA installed to home screen.
3. **Ledger row delete fires instantly with no confirmation, and is invisible on touch.** [src/pages/Ledger.tsx#L452-L454](src/pages/Ledger.tsx#L452-L454) wraps edit/delete in `opacity-0 group-hover:opacity-100` (no `max-md:opacity-100` fallback as TodayLens has at [src/pages/lenses/TodayLens.tsx#L357](src/pages/lenses/TodayLens.tsx#L357)) — on mobile they are unreachable. And `deleteTx.mutate(t.id)` runs without `confirm()` while every other page uses `confirm(...)`. Both a consistency and a destructive-action safety violation.
4. **`--fg-subtle` fails WCAG AA in light mode.** Light: `#9ca3af` on `#fafafc` ≈ **2.7 : 1**. Dark: `#71717a` on `#09090c` ≈ **4.0 : 1**. Both fail AA body-text 4.5:1; light fails AA-Large 3:1 too. Used pervasively for metadata, dates, "uncategorised", labels — see e.g. [src/pages/Ledger.tsx#L388](src/pages/Ledger.tsx#L388), [src/components/CommandPalette.tsx#L46](src/components/CommandPalette.tsx#L46), every lens.
5. **Typography is not on the HIG SF scale.** Tailwind's default ramp (`text-xs 12 / sm 14 / base 16 / lg 18 / xl 20 / 2xl 24 / 3xl 30 / 4xl 36 / 5xl 48`) is reused as-is. There is no Headline-17-semibold, no Body-17, no Callout-16, no Subhead-15, no Footnote-13. Body copy is 14px (`text-sm`), one notch below Apple's 17pt body. Page H1s jump straight from 24 → 30, skipping Title 1 (28) and Title 2 (22). Worse, ~20+ uses of arbitrary `text-[10px]` / `text-[11px]` (px, not rem) defeat both the SF scale and Dynamic Type.

## Findings

### 1. Typographic scale

**Current state**
- System stack is correct: [tailwind.config.js#L31-L46](tailwind.config.js#L31-L46) declares `-apple-system, BlinkMacSystemFont, "SF Pro Text", "SF Pro Display", …`.
- Page titles use `text-2xl md:text-3xl font-semibold` (24 → 30) on Today/Week/Month/Forecast/Plan/Categories/Assets/Recurring; Ledger uses `text-xl md:text-3xl` ([src/pages/Ledger.tsx#L271](src/pages/Ledger.tsx#L271)) — already inconsistent.
- Section H2s are bare `font-semibold` (= 14px because parent inherits `text-sm`), e.g. [src/pages/lenses/ForecastLens.tsx#L242](src/pages/lenses/ForecastLens.tsx#L242).
- Body text defaults to `text-sm` (14px) in cards and lists, e.g. Ledger entry rows ([src/pages/Ledger.tsx#L435](src/pages/Ledger.tsx#L435)).
- Hero numbers: Forecast `text-3xl md:text-4xl` (30/36), Week `text-4xl md:text-5xl` (36/48), Plan `text-2xl md:text-3xl`. No shared "hero number" style.
- 20+ uses of arbitrary `text-[10px]` and `text-[11px]` for tags/labels/kbd hints (e.g. [src/components/Layout.tsx#L78,L82,L114](src/components/Layout.tsx#L78), every lens, RebalanceStep).

**Gap vs HIG**
- HIG iOS SF text styles are: Large Title 34 / Title 1 28 / Title 2 22 / Title 3 20 / Headline 17 sb / Body 17 / Callout 16 / Subhead 15 / Footnote 13 / Caption 1 12 / Caption 2 11. The app's body is 14px — between Subhead and Footnote — and the page title `text-3xl` (30) is between Title 1 (28) and Large Title (34). The ramp is "close to Material" rather than HIG.
- `text-[10px]` / `text-[11px]` in **px** does not scale with `html { font-size: ... }` user override (Dynamic Type proxy on the web). A user who bumps default font size sees the body grow but those tags stay at 10/11 px.
- No `tracking` adjustments per size — HIG SF Pro switches between SF Pro Text and SF Pro Display at 20pt with different optical tracking; the stack lists both fonts but never selects them deliberately.

**Recommended change**
Add explicit HIG type tokens to `tailwind.config.js`:
```js
fontSize: {
  'caption-2':  ['0.6875rem', { lineHeight: '0.8125rem', letterSpacing: '0.005em' }], // 11
  'caption-1':  ['0.75rem',   { lineHeight: '1rem',      letterSpacing: '0' }],        // 12
  'footnote':   ['0.8125rem', { lineHeight: '1.125rem',  letterSpacing: '-0.005em' }], // 13
  'subhead':    ['0.9375rem', { lineHeight: '1.25rem',   letterSpacing: '-0.01em' }],  // 15
  'callout':    ['1rem',      { lineHeight: '1.3125rem', letterSpacing: '-0.015em' }], // 16
  'body':       ['1.0625rem', { lineHeight: '1.375rem',  letterSpacing: '-0.022em' }], // 17
  'headline':   ['1.0625rem', { lineHeight: '1.375rem',  letterSpacing: '-0.022em', fontWeight: '600' }],
  'title-3':    ['1.25rem',   { lineHeight: '1.5625rem', letterSpacing: '-0.024em' }], // 20
  'title-2':    ['1.375rem',  { lineHeight: '1.75rem',   letterSpacing: '-0.026em' }], // 22
  'title-1':    ['1.75rem',   { lineHeight: '2.125rem',  letterSpacing: '-0.03em' }],  // 28
  'large-title':['2.125rem',  { lineHeight: '2.5625rem', letterSpacing: '-0.034em', fontWeight: '700' }], // 34
},
```
Then replace `text-2xl md:text-3xl font-semibold` → `text-title-1 md:text-large-title`, `text-sm` body content → `text-body`, all `text-[10px]` / `text-[11px]` → `text-caption-2`. Bare `font-semibold` headers → `text-headline`.

**Effort: M · Impact: high** — purely token swap once the tokens are introduced; restores HIG cadence app-wide.

### 2. Concentric corner radii

**Current state**
Six radii actively used on similar surfaces:
- `rounded-md` (6) — Ledger select buttons [Ledger.tsx#L342,L352](src/pages/Ledger.tsx#L342)
- `rounded-lg` (8) — day badge [Ledger.tsx#L360](src/pages/Ledger.tsx#L360), color swatches [Categories.tsx#L102](src/pages/Categories.tsx#L102), GoalAlertRibbon icon, MonthLens stat icons, palette button, CommandPalette items, btn-ghost close in Modal desktop
- `rounded-xl` (12) — `.btn`, `.input`, `.chip`, sidebar nav links, Asset cards
- `rounded-2xl` (16) — `.card`, desktop dialog
- `rounded-3xl` (24) — mobile dialog top `rounded-t-3xl`
- `rounded-[44px]` — mobile floating nav (matches iPhone screen)
- `rounded-full` — chips, FAB, sticky toolbar pills
- `!rounded-full` overrides on `.btn` in Ledger toolbar [L286,L296,L303-305](src/pages/Ledger.tsx#L286) — buttons using `.btn` *and* `!rounded-full` together — Tailwind's `.btn @apply rounded-xl` is being shouted-down with `!`.

Concentricity check — `.card` (16) with default `p-4` (16) wrapping `.input` (12): outer-padding 16, outer-radius 16, inner-radius 12 → outer − padding = 0 ≠ inner radius (need 16 − padding ≈ inner; padding should be 4 for 16 / 12 concentric). Currently neither concentric nor by design.

Mobile dialog top `rounded-t-3xl` (24) with sticky header `pb-3 border-b` and inner content `px-5 py-4` is not visibly concentric with anything inside it.

**Gap vs HIG**
HIG and SwiftUI's "continuous" corner system enforce `outerRadius − padding = innerRadius` so nested rectangles share a centre of curvature ("squircle" continuous corners). The app uses standard `border-radius` (not `corner-style: continuous` / `border-radius: 12px / 16px` superellipse), and doesn't enforce the math.

**Recommended change**
1. Define a 4-step radius scale in config and use only those:
   - `--r-sm: 8px` — chips, day badge, kbd
   - `--r-md: 12px` — buttons, inputs, inline pills
   - `--r-lg: 16px` — cards, desktop dialog
   - `--r-xl: 24px` — bottom sheets, large hero cards
   - `--r-pill: 9999px` — tab pills, FAB
   - `--r-device: 44px` — only the floating mobile chrome that hugs the screen edge
2. Establish concentric padding contracts: any `card` (16) that wraps a button (12) should have `p-1` outer padding (4px). For `card` with `p-4` (16), nested elements should be `rounded-lg` (16 − 16 = 0 → radius-less or rounded-sm). Currently `.card` uses `rounded-2xl` (16) with `p-4` and contains `rounded-xl` (12) buttons — off by 4px.
3. Approximate continuous corners (squircle look) via `border-radius` boost + a hairline inner shadow, or better, use the proposed CSS `corner-shape: superellipse(2.5)` with a `@supports` guard.
4. Strip `!rounded-full` overrides on `.btn`. Either define `.btn-pill` or drop `.btn` from Ledger's toolbar buttons.

**Effort: M · Impact: med** — visible across every surface but the work is mostly find-and-replace.

### 3. Liquid Glass / vibrancy

**Current state**
- `.glass` definition is strong ([src/index.css#L120-L168](src/index.css#L120-L168)).
- Used in: mobile bottom nav, mobile FAB, Dashboard lens pills, Ledger sticky toolbar, Ledger summary bottom-sheet trigger, desktop dialog.
- **Sidebar** uses `bg-bg-elev/50 backdrop-blur-sm` ([Layout.tsx#L45](src/components/Layout.tsx#L45)) — a thin, non-vibrant material; not glass.
- **Sticky page headers** — Dashboard lens pills are sticky and glassy, but the page title above them is a plain `<div>` that scrolls away with no scroll-edge effect. Other pages (Ledger, Categories, Assets, Recurring) keep their H1 in normal flow with no scroll-edge transition.
- **Modal overlay** uses only `backdrop-blur-sm` over `bg-black/55` ([Modal.tsx#L30](src/components/ui/Modal.tsx#L30)) — fine.
- **Mobile dialog header** uses `bg-bg-card/95 backdrop-blur-md` (95% opaque → not vibrant) — should be glassier so the body content shows through.
- **Ledger summary bottom-sheet trigger** at `bottom-[calc(5rem+env(safe-area-inset-bottom))]` ([Ledger.tsx#L568](src/pages/Ledger.tsx#L568)) sits on top of the floating glass tab bar — two glass elements stacked; works visually but the FAB sits at the same z = 40 → potential overlap.

**Gap vs HIG**
HIG Liquid Glass calls for translucent material **wherever floating chrome obscures content** so the underlying content informs the chrome's tint. Sidebar and the in-flow page headers are missing the effect. There is no scroll-edge appearance change (HIG: nav bar acquires translucent background only when content scrolls under it).

**Recommended change**
1. Replace sidebar background with `.glass` (a softer dark-glass: lower saturation, lower brightness). Keep border on the right edge.
2. Wrap each page's H1 + toolbar in a sticky `<header>` that swaps to `.glass` after a small scroll threshold (use `IntersectionObserver` on a sentinel `<div>` or `position: sticky` + `top: -1px` + `:not(:stuck)` polyfill via `--scroll-y` CSS var).
3. Replace mobile modal sticky header `bg-bg-card/95 backdrop-blur-md` with `glass` (dropping the gradient-from-white tone in favor of `bg-bg-card/70` for legibility).

**Effort: M · Impact: high** — biggest visible "iOS 26" upgrade.

### 4. Safe-area insets

**Current state**
- `<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover" />` ✓ ([index.html#L7](index.html#L7))
- `apple-mobile-web-app-status-bar-style: black-translucent` ✓ ([index.html#L11](index.html#L11)) — required for content under the notch.
- Top: `pt-[max(env(safe-area-inset-top),12px)]` on `<main>` ([Layout.tsx#L136](src/components/Layout.tsx#L136)).
- Bottom: `pb-[calc(5rem+env(safe-area-inset-bottom))]` ([Layout.tsx#L136](src/components/Layout.tsx#L136)) — accounts for floating tab bar plus home indicator.
- Mobile tab bar: `mb-[calc(max(env(safe-area-inset-bottom),6px)-4px)]` ([Layout.tsx#L104](src/components/Layout.tsx#L104)) — `-4px` makes it hug the home-indicator edge; intentional but slightly fragile.
- FAB: `bottom-[calc(5rem+env(safe-area-inset-bottom))]` ✓.
- Modal mobile footer: `pb-[max(env(safe-area-inset-bottom),12px)]` ✓.
- Toast: `top-[max(env(safe-area-inset-top),0.75rem)]` ✓.
- Dashboard sticky lens bar: `top-[calc(env(safe-area-inset-top)-0.25rem)]` ([Dashboard.tsx#L41](src/pages/Dashboard.tsx#L41)) — subtracting 0.25rem can pull the bar above the safe area on devices with very small inset (< 4px), risking notch overlap. Use `max(...)` instead.
- Ledger sticky toolbar: `top-[calc(env(safe-area-inset-top)+0.125rem)]` ✓.
- PublicShare: `pt-[max(env(safe-area-inset-top),24px)]` ✓.

**Gap vs HIG**
- **No left/right insets** anywhere. iPhone in landscape with a Dynamic Island has `safe-area-inset-left` and `safe-area-inset-right`. Floating tab bar uses `inset-x-4` (fixed 16px) — content gets clipped by the island when phone is rotated.
- Dashboard lens bar's negative-clamp could draw a sliver under the status bar on iPad / older iPhones.

**Recommended change**
- Replace `inset-x-4` on mobile nav with `left-[max(env(safe-area-inset-left),16px)] right-[max(env(safe-area-inset-right),16px)]`.
- On `<main>`: `px-[max(env(safe-area-inset-left),0px)]` with default page padding additive.
- Fix Dashboard lens bar: `top-[max(env(safe-area-inset-top),0px)]` — drop the `-0.25rem`.

**Effort: S · Impact: med** — only affects landscape-rotated iPhones, but it's a HIG hard rule.

4. Lens chips and Forecast horizon chips: `min-h-[44px] px-4`.
5. Mobile dialog close: `w-11 h-11` (44).

**Effort: M · Impact: high** — many sites, but mechanical.

### 6a. Bottom-sheet vs centered modal

**Current state**
[src/components/ui/Modal.tsx](src/components/ui/Modal.tsx) is exemplary:
- `max-md:items-end md:items-center md:justify-center` ✓
- `max-md:rounded-t-3xl max-md:animate-sheet-up` ✓

- Add a "medium" detent for `AddTransactionDialog` form step (it's tall) — set initial `y` via `framer-motion` to ~40vh and let drag pull up to 88vh.

```ts
function usePullToRefresh(onRefresh: () => Promise<void>) {
```

**Effort: M · Impact: med** — net-new, but contained.

### 6c. Segmented control for time lenses

**Current state**
[src/pages/Dashboard.tsx#L41-L58](src/pages/Dashboard.tsx#L41) — six pill buttons in a horizontally scrolling row. Active = `bg-accent text-accent-fg shadow-soft`, inactive = `glass text-fg`. No sliding indicator, no shared track.

**Gap vs HIG**
HIG iOS segmented control is a **single rounded rectangle** containing N equal-width segments with a **sliding selected pill** that animates between segments (Apple uses `matchedGeometryEffect` in SwiftUI). The current implementation is closer to "filter chips" than a segmented control.

With six segments, however, a true iOS segmented control would not fit on phone width — Apple's own apps switch to a horizontal scroll bar (Calendar) or a Tab Bar (Today/Week/Month is a Tab Bar in iOS Calendar's day view). Six lenses is too many for a single pill.

**Recommended change**
Two viable approaches:
1. **Reduce to 3 + overflow** ("Today / Week / Month" as a true segmented control with sliding indicator; "Forecast / Plan / Shared" promoted to a separate overflow menu or distinct tab).
2. **Keep six but adopt a sliding indicator**: wrap items in a single `glass` track, render an absolutely-positioned `bg-accent` pill whose `left`/`width` is animated via `framer-motion` `layout` prop or `transform` keyed off the active index.

Sample for option 2:
```tsx
<div className="relative glass rounded-full p-1 inline-flex">
  <motion.div
    layoutId="lens-pill"
    className="absolute inset-y-1 rounded-full bg-accent"
    style={{ left: pillLeft, width: pillWidth }}
    transition={{ type: 'spring', stiffness: 400, damping: 35 }}
  />
  {LENSES.map(... <button className="relative z-10 px-4 py-2 ..." />)}
</div>
```

**Effort: M · Impact: high** — the lens switcher is the most-used UI in the app.

### 6d. Swipe-actions on ledger rows

**Current state**: not implemented. Edit/delete revealed via `opacity-0 group-hover:opacity-100` on desktop; on mobile they are invisible and unreachable in Ledger.tsx (TodayLens has the `max-md:opacity-100` fallback). Delete in Ledger fires immediately ([Ledger.tsx#L454](src/pages/Ledger.tsx#L454)) without `confirm()`.

**Gap vs HIG**
HIG iOS list pattern: swipe-left → trailing actions (Delete red, Edit blue). Trailing edge swipe is the canonical destructive affordance. App has no equivalent.

**Recommended change**
Wrap each ledger row in a swipeable container using `framer-motion`:
```tsx
<motion.div
  drag="x"
  dragConstraints={{ left: -160, right: 0 }}
  dragElastic={{ left: 0.2, right: 0 }}
  onDragEnd={(_, info) => {
    if (info.offset.x < -120) { confirmAndDelete() }
    else { animate(x, 0) }
  }}
>
  <div className="absolute right-0 inset-y-0 flex items-stretch">
    <button className="bg-accent w-20 text-white">Edit</button>
    <button className="bg-negative w-20 text-white">Delete</button>
  </div>
  <div ref={rowRef} className="bg-bg-card">{rowContent}</div>
</motion.div>
```
Add a haptic `navigator.vibrate(15)` at the threshold crossing (see #9).

**Effort: L · Impact: high** — biggest UX upgrade for the most-used page.

### 8. Accessibility

#### 8a. Dynamic Type / font scaling
**Current state**: Tailwind defaults are rem-based ✓. But ~20 occurrences of `text-[10px]`, `text-[11px]` in **px** ([grep_search results above](src/components/Layout.tsx#L78)). Same for hard-coded `leading-tight`, `pt-[max(env(safe-area-inset-top),12px)]` (px) — minor.

**Gap**: Users who set browser default font ≠ 16px will see Tailwind classes scale but `text-[10px]` stay frozen. iOS Dynamic Type emulation in browsers is partial; the right web equivalent is *honouring* the root font-size — which px-arbitrary classes break.

**Recommended change**: replace `text-[10px]` → `text-[0.625rem]` and `text-[11px]` → `text-[0.6875rem]`, or better, the `text-caption-2` token from #1.

**Effort: S · Impact: med**

#### 8b. `prefers-reduced-motion`
**Current state**: zero matches across the codebase. `framer-motion` motion components don't call `useReducedMotion()`. Tailwind animations (`animate-fade-in`, `animate-slide-up`, `animate-sheet-up`) play regardless.

**Gap**: WCAG 2.3.3 + HIG accessibility. `.btn:active { transform: scale(0.94) }`, the sheet drag, the spring-back, all play for users who explicitly opt out of motion.

**Recommended change**
1. Add the reduce-motion guard to `index.css`:
   ```css
   @media (prefers-reduced-motion: reduce) {
     *, *::before, *::after {
       animation-duration: 0.01ms !important;
       animation-iteration-count: 1 !important;
       transition-duration: 0.01ms !important;
       scroll-behavior: auto !important;
     }
     .btn:active, button:not(.btn):not([data-no-press]):active { transform: none !important; }
   }
   ```
2. In `framer-motion` components, gate the `initial`/`animate` via `useReducedMotion()`:
   ```ts
   const reduce = useReducedMotion()
   <motion.form initial={reduce ? false : {opacity:0,x:-8}} ...>
   ```

**Effort: S · Impact: high (WCAG)**

### 9. Haptics

**Current state**: zero `navigator.vibrate(...)` calls anywhere in the codebase.

**Gap**: HIG haptics taxonomy: *Selection* (12ms), *Light* (10–20ms), *Medium* (25ms), *Heavy* (40ms), *Success* (15ms+30ms pulse), *Warning*, *Error*. Web equivalent via `navigator.vibrate` is supported in Chrome Android and (since iOS 17.4) iOS PWAs in standalone mode.

Ideal trigger points missing:
- Save transaction succeeds → `navigator.vibrate(10)` (light).
- Apply rebalance → `navigator.vibrate([15, 30, 15])` (success pattern).
- Delete (after confirm) → `navigator.vibrate(40)` (heavy).
- Toggle theme / lens switch → `navigator.vibrate(8)` (selection).
- Sheet swipe-to-dismiss crosses threshold → `navigator.vibrate(10)`.
- Day-badge tap in select mode → `navigator.vibrate(8)`.

**Recommended change**
Add a small `lib/haptics.ts`:
```ts
const supported = typeof navigator !== 'undefined' && 'vibrate' in navigator
export const haptics = {
  selection: () => supported && navigator.vibrate(8),
  light:     () => supported && navigator.vibrate(12),
  medium:    () => supported && navigator.vibrate(25),
  heavy:     () => supported && navigator.vibrate(40),
  success:   () => supported && navigator.vibrate([12, 30, 12]),
  warning:   () => supported && navigator.vibrate([20, 60, 20]),
  error:     () => supported && navigator.vibrate([40, 30, 40]),
}
```
Wire into `useUpsertTransaction` `onSuccess`, `useApplyRebalance` `onSuccess`, `useDeleteTransaction` `onSuccess`, `toggleTheme` in `store/ui.ts`, and the `onDragEnd` of `Modal`.

**Effort: S · Impact: high** — instant perceived-quality lift.

### 12. Harmony / device-corner concentricity

**Current state**
- Mobile floating tab bar `rounded-[44px]` ([Layout.tsx#L104](src/components/Layout.tsx#L104)) — matches iPhone 14/15/16 screen radius (~47.33pt, close enough).
- Mobile dialog `rounded-t-3xl` (24) at the top — sheet doesn't reach the screen edge so this isn't a device-concentricity case; reasonable.
- FAB `rounded-full w-14 h-14` (56) — fine.
- The PWA does not use `display: standalone` content rounding (CSS `border-radius` on `<body>`) — irrelevant since the iOS PWA shell already matches the device.
- No notch-aware `--device-radius` variable.

**Gap**: minor. The tab bar's `[44px]` is hard-coded; iPad has different curvature, iPhone SE has square corners. iPad in landscape would show the same pill with a 44px radius floating in the middle of a square-cornered screen, which looks slightly "off".

**Recommended change**
Define `--device-radius: 44px` and a tighter value for iPad / desktop via media queries:
```css
:root { --device-radius: 22px; }
@media (max-width: 767px) { :root { --device-radius: 44px; } }
@supports (padding: env(safe-area-inset-bottom)) and (max-width: 430px) {
  :root { --device-radius: max(env(safe-area-inset-bottom) * 1.5, 44px); }
}
```
Then `rounded-[var(--device-radius)]`.

**Effort: S · Impact: low**
